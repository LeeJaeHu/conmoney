# PRD — 스트레스 없는 월 예산 에이전트 (가칭)

- 작성: 2026-10-13 · 상태: 초안 v0.2 (특이 지출·예산 기간·할부 결정 반영) · 작성자: 이재후
- 플랫폼: Android (개인 사용, APK 직접 설치)

---

## 1. 배경과 문제

- 월초에는 신경 쓰지 않고 쓰다가, 월말에 결제 기록을 보고 아끼려고 한다. 그런데 월말에 공과금과 통신비가 빠져나가면서 생각보다 많이 쓰게 된다.
- 네이버 자산 같은 서비스로 카드별 사용액을 볼 수는 있다. 하지만 **총액을 보는 것 자체가 스트레스**라 잘 들어가지 않고, 잊고 지내다 보면 어느 순간 많이 써버린다.
- 즉 문제는 데이터가 없는 것이 아니다. **언제, 어떤 형태로 알려주느냐**가 문제다.

## 2. 목표와 비목표

### 목표
1. 정기 지출을 미리 반영한 **"오늘 쓸 수 있는 금액"** 을 언제든 한눈에 본다.
2. 결제 직후 **카테고리·특이 지출 여부·메모**를 몇 초 안에 기록한다.
3. 구매를 고민할 때 **내 과거 소비 패턴을 근거로** 살지 말지 조언을 받는다.
4. 앱이 **필요한 순간에만** 먼저 알려준다.

### 비목표 (이번 버전에서 하지 않음)
- 투자·대출 상품 추천
- 은행·카드사 API나 마이데이터 직접 연동(개인은 사용 불가)
- 플레이스토어 배포, 여러 사용자 지원
- 실제 결제나 송금 같은 금융 거래 실행

## 3. 핵심 시나리오

1. **결제 직후:** 스타벅스 결제 → 현대카드 앱 푸시 → 앱 알림 "스타벅스 6,500원 · 카페·간식?" → [맞아요] 또는 탭해서 확인 시트에서 카테고리·특이 지출·메모 입력
2. **아침에 확인:** 앱을 열면 "오늘 쓸 수 있는 금액 18,000원"이 크게, 그 아래 "이번 달 남은 예산 216,000원 (통신비·가스비 예정분 제외 후)"이 작게 보인다
3. **구매 고민:** "키보드 15만 원 살까?" → 남은 예산·남은 일수·평소 월말 소비·예정 고정비를 근거로 판단과 대안 제시
4. **먼저 알림:** "이틀 뒤 통신비 65,000원이 나가요. 오늘부터 하루 가능 금액이 12,000원으로 줄어요."
5. **월말 회고:** 카테고리별·기간별 지출 보기. 특이 지출은 따로 표시

## 4. 기능 요구사항

우선순위: **P0** = 10/25 전 최소 버전 / **P1** = 지원 후 / **P2** = 여유 있을 때

### F1. 카드 등록과 데이터 가져오기 안내 (P0)
- 카드 목록에서 내 카드를 선택한다(카드사, 상품명).
- 카드마다 다음을 연결한다.
  - **알림 출처:** 현대카드 앱 푸시 / 카카오톡 롯데카드 알림톡 / 토스 앱 푸시
  - **과거 기록 가져오는 방법 안내:** 예) 롯데카드 = 카톡 대화 내보내기, 현대카드 = 홈페이지 이용내역 다운로드(경로 확인 필요), 토스 = 거래내역서 발급
  - **결제일, 전월 실적 기준 금액**(P1에서 상품설명서 근거로 자동 채움)
- 수락 기준: 등록한 카드의 알림만 결제로 인식한다. 등록하지 않은 앱의 알림은 무시한다.

### F2. 결제 알림 감지와 파싱 (P0)
- Android 알림 접근 권한으로 지정 앱의 알림을 읽는다.
- 추출 항목: 카드, 금액, 가맹점, 일시, 승인/취소, 일시불/할부(개월), 국내/해외
- 예외 처리
  - **결제 취소**: 원거래를 찾아 상쇄한다. 못 찾으면 음수 거래로 저장하고 확인을 요청한다.
  - **중복**: 같은 결제가 여러 경로로 들어오면(예: 토스 교통 후불이 다른 카드로 청구) 하나로 합친다.
  - **파싱 실패**: 원문을 보관하고 "확인 필요" 목록에 넣는다. 조용히 버리지 않는다.
- 수락 기준: 샘플 평가셋에서 금액·가맹점·일시 추출 정확도 98% 이상, 취소 처리 100%

### F3. 결제 확인 (카테고리 · 특이 지출 · 메모) (P0)
- 결제가 인식되면 앱 알림을 보낸다: "{가맹점} {금액} · {추천 카테고리}?"
  - 알림 버튼: **[맞아요]** (추천 카테고리로 확정) / **[수정]** (확인 시트 열기)
- **확인 시트** (위에서 아래 순서)
  1. 결제 정보: 가맹점, 금액, 카드, 시간
  2. **카테고리 선택**: 칩 형태. 추천 카테고리가 미리 선택됨
  3. **특이 지출 여부**: 토글. 기본값 꺼짐
  4. **메모**: 자유 입력(예: "동기 생일 선물")
  5. 저장
- 확정하지 않은 결제는 "미확인"으로 남아 홈 화면에 개수만 표시한다(지출 계산에는 포함).
- 같은 가맹점에서 카테고리를 바꾸면 다음부터 그 카테고리를 추천한다.

**기본 카테고리:** 식비 / 카페·간식 / 교통 / 게임 / 쇼핑 / 구독 / API / 통신 / 공과금 / 의료 / 교육 / 영화 / 경조사·선물 / 연회비 / 기타 (편집 가능)

**특이 지출의 정의 (확정 10/13):** 평소에 없는 일회성 지출(예: 가전 구매, 여행, 경조사).
- 예산 계산(남은 예산, 오늘 쓸 수 있는 금액)에는 **포함**한다.
- "평소 소비 패턴" 통계(일평균, 월말 평균)와 예측에서는 **제외**한다. 그래야 다음 달 조언이 한 번의 큰 지출에 휘둘리지 않는다.

### F4. 예산 설정과 홈 화면 (P0)
- 월 목표 금액을 설정한다. **예산 기간은 매월 1일~말일로 고정한다(확정 10/13).**
- **목표 방식을 고른다(확정 10/13):** 고정(매월 같은 금액) 또는 단계적(시작 금액에서 최종 목표까지 몇 달에 걸쳐 내림, 예: 80만 → 67만 → 54만)
- **할부 결제는 매달 할부금만 해당 월 지출로 반영한다(확정 10/13).**
  - 할부 결제가 들어오면 개월 수만큼 월별 할부금 일정을 만든다.
  - 이번 달 할부금은 확정 지출(S)에, 다음 달부터의 할부금은 그 달의 예정 지출(F)로 미리 잡힌다.
  - 할부금이 나누어떨어지지 않으면 첫 달에 나머지를 더한다(카드사 실제 청구 방식과 다를 수 있어 P1에서 명세서로 검증).
- 홈 화면에 **오늘 쓸 수 있는 금액**(크게)과 **이번 달 남은 예산**(작게)을 함께 보여준다(확정 10/13).
- 초과하면 0원으로만 보여주지 않고 **오늘·이번 달 각각 얼마나 넘었는지** 금액으로 보여준다(확정 10/13).
- 총 사용액은 홈 화면에 크게 보여주지 않는다. 상세 화면에서만 본다(스트레스 최소화 원칙).
- 계산 정의는 7장 참고

### F5. 정기 지출과 예정 지출 (P0: 수동 등록 + 자동 탐지 제안 / P1: 공과금 추정)
- 정기 지출 항목: 이름, 금액(고정 또는 추정), 결제일, 결제 카드
- **자동 탐지:** 같은 가맹점에서 비슷한 금액이 매달 비슷한 날짜에 결제되면 "정기 지출로 등록할까요?"라고 제안한다.
- **예정 지출 선차감:** 이번 기간에 아직 결제되지 않은 정기 지출은 이미 쓴 것처럼 남은 예산에서 미리 뺀다. 실제 결제가 들어오면 예정분과 맞바꾼다(차액 반영).
- **공과금 추정 (P1):** 전기·가스비는 전년 동월 금액을 기본으로 하고, 전월 대비 변화로 보정한다. 기록이 없으면 사용자 입력값을 쓴다. 고지서 사진 입력(이미지 인식)은 P2.

### F6. 구매 상담 에이전트 (P0)
- 채팅 입력: "키보드 15만 원 살까?", "이번 주말에 5만 원 써도 돼?"
- 에이전트는 툴로 숫자를 조회하고, 판단과 이유, 대안을 말한다(5장).
- 응답 형식
  1. **판단**: 괜찮아요 / 조건부 / 미루는 걸 추천
  2. **근거 숫자**: 남은 예산, 남은 일수, 예정 고정비, 평소 남은 기간 소비
  3. **대안**: 예) "다음 달 1일 이후", "이번 주 외식을 2번 줄이면 가능"
- 말투: 비난하지 않는다. 총액보다 "앞으로"에 초점을 둔다.

### F7. 먼저 알려주기 (P0: 규칙 기반 / P1: 에이전트 판단)
- 결제 확인 알림 외에 **하루 최대 1회**만 보낸다.
- 알림 조건
  - 오늘 쓸 수 있는 금액이 0원 아래로 내려갔을 때
  - 큰 정기 지출이 2일 안에 나갈 때
  - 남은 예산이 예정보다 빠르게 줄어들 때(평소 패턴 대비)
  - (P1) 카드 전월 실적 마감 3일 전, 부족분이 작을 때
- 조용한 시간대(예: 23시~8시)에는 보내지 않는다.

### F8. 카테고리·기간 보기 (P0)
- 기간 선택(이번 달, 지난달, 최근 3개월, 직접 지정)
- 카테고리별 합계와 비율, 카테고리를 누르면 거래 목록(메모 포함)
- 특이 지출 포함/제외 토글

### F9. 카드 실적 확인 (P1)
- 카드별 이번 달 실적 인정 금액과 목표까지 남은 금액을 보여준다.
- 실적에서 빠지는 항목(공과금, 상품권, 할부 등)은 **카드 상품설명서 PDF를 검색해 조항을 근거로** 판단한다. 근거를 못 찾으면 "확인 불가"로 표시한다.
- 실적을 채우려고 추가 소비를 권하지 않는다. "어느 카드로 결제하면 좋은지"만 안내한다.

### F11. 돈 상담과 상담 기록 (P1, 추가 10/13)
- 구매 상담 외에 "이번 달 왜 많이 썼지?", "배달 줄이는 방법" 같은 자유 상담. 툴로 실제 숫자를 보고 2단계 모델이 답한다.
- 상담마다 **요약과 결정**(예: "키보드 15만 원, 다음 달로 미룸")을 폰 안에만 저장한다. 서버에는 저장하지 않는다.
- 미룬 구매는 다음 달 1일에 다시 묻는다("지난달 미룬 키보드 아직 필요해요?").
- 결정을 지켰는지 실제 거래와 대조해 보여준다(지표: 상담 후 미룬 구매 중 실제로 안 산 비율).

### F10. 과거 기록 가져오기 (P1)
- 롯데카드 카톡 대화 내보내기 파일(.txt), 카드사 엑셀 이용내역 업로드 → 파싱 → 중복 제거 후 저장
- 가져온 기록으로 정기 지출 탐지와 평소 패턴 통계를 바로 계산한다.

## 5. 에이전트 설계

### 역할 분담
- **코드(앱):** 모든 금액 계산, 예산, 통계, 예측
- **LLM:** 의도 파악, 애매한 가맹점의 카테고리 추천, 상품설명서 근거 찾기, 설명과 말투
- **원칙:** LLM은 툴이 준 숫자만 인용한다. 응답의 숫자는 툴 결과와 대조해 다르면 다시 생성한다.

### 툴 (앱 안에서 실행)
| 툴 | 반환 |
|---|---|
| `get_budget_status()` | 예산, 확정 지출, 예정 지출, 남은 예산, 남은 일수, 오늘 가능 금액 |
| `get_upcoming_fixed(days)` | 기간 내 예정된 정기 지출 목록 |
| `get_spending_pattern(window)` | 과거 N개월의 같은 기간(예: 월말 12일) 평균·중앙값 소비. 특이 지출 제외 |
| `simulate_purchase(amount, date)` | 구매 시 남은 예산, 오늘 가능 금액, 예상 월말 초과액 |
| `get_category_summary(period)` | 카테고리별 합계 |
| `search_card_terms(card, query)` (P1) | 상품설명서에서 찾은 조항과 출처 |
| `suggest_category(merchant)` | 규칙 → 과거 기록 → LLM 순서로 추천 |

### 개인정보를 지키는 에이전트 루프
1. 앱이 사용자 질문과 툴 정의를 서버(Cloud Run 함수)로 보낸다.
2. 서버는 LLM을 호출하고 툴 호출 요청을 앱으로 돌려준다.
3. **툴은 앱 안에서 실행한다.** 거래 원본은 폰 밖으로 나가지 않고, LLM은 집계된 결과만 본다.
4. 서버는 LLM API 키를 숨기는 중계 역할만 한다. 대화 로그는 저장하지 않는다(디버그 모드 제외).

### 가드레일
- 카드번호, 승인번호 같은 식별 정보는 서버로 보내기 전에 가린다.
- **알림 텍스트는 신뢰하지 않는 입력이다.** 가맹점명에 지시문 같은 문장이 들어 있어도 명령으로 취급하지 않는다(프롬프트 인젝션 방어).
- 투자·대출 권유를 하지 않는다. 범위 밖 질문은 정중히 거절한다.
- 숫자 검증에 실패하면 숫자 없이 "계산을 확인하지 못했어요"라고 답한다.

### 비용·지연 원칙
- 결제 파싱과 흔한 가맹점 분류는 앱에서 규칙으로 처리한다. **애매한 경우만 LLM을 호출한다.**
- **작업마다 모델을 다르게 쓴다(확정 10/13).** 어떤 단계를 쓸지는 LLM이 아니라 앱 코드가 정한다.
  | 단계 | 작업 | 모델 |
  |---|---|---|
  | 0 | 알림 파싱, 금액 계산, 아는 가맹점 분류 | 앱 코드(AI 없음) |
  | 1 | 처음 보는 가맹점 분류, 질문 종류 파악 | **jev**(TypeSafe AI, 선택지 중 하나를 확신도와 함께 고르는 모델). 실패 시 저가 LLM |
  | 2 | 구매 상담, 분석, (P1) 돈 상담 | 상위 LLM 1개. Gemini·OpenAI·Grok을 구매 상담 평가셋으로 비교해 결정 |
- 1단계 답이 숫자 검증에 두 번 실패하면 2단계로 올린다. 월 API 비용 목표는 1만 원 이하이며, 상한에 가까우면 2단계도 1단계 저가 모델로 내린다.
- 서버는 "작업 → 모델" 설정 파일로 모델을 고른다. 모델을 바꿔도 코드는 바꾸지 않는다.

## 7. 계산 정의

- 기간 = 매월 1일 ~ 말일
- **B** = 이번 달 목표 예산
- **S** = 이번 달 확정 지출 합계(취소 반영, 특이 지출 포함). **할부는 이번 달 회차 금액만 포함**
- **F** = 이번 달에 아직 결제되지 않은 정기 지출 예정액(추정 포함) + 이번 달 청구 예정인 할부금 중 S에 없는 것
- **남은 예산 R = B − S − F**
- **오늘 쓸 수 있는 금액** = (오늘 0시 기준 남은 예산 ÷ 오늘 포함 남은 일수) − 오늘 쓴 금액
  - 하루 기준액은 0시에 한 번 계산한다. 그날 쓴 만큼만 줄어들어 하루 안에서 숫자가 흔들리지 않는다.
  - 음수가 되면 0원으로 표시하고 초과액을 따로 보여준다.
- **평소 패턴 P(window)** = 최근 3개월(특이 지출 제외)의 같은 남은 기간 소비 중앙값
- **예상 월말 지출** = S + F + P(남은 기간)
- **구매 판단 규칙 (초안)**
  - 구매 후 예상 월말 지출 ≤ B → 괜찮아요
  - B 초과분이 B의 10% 이하 → 조건부(대안 제시)
  - 그 이상 → 미루는 걸 추천

## 8. 평가 계획

| 대상 | 방법 | 목표 |
|---|---|---|
| 알림 파싱 | 실제 알림 샘플(카드사별, 취소·할부·해외 포함)로 만든 평가셋 | 금액·가맹점·일시 98% 이상, 취소 100% |
| 카테고리 추천 | 내가 직접 붙인 정답 대비 정확도, LLM 호출 비율, 건당 비용 | 정확도 85% 이상, LLM 호출 30% 이하 |
| 월말 예측 | 과거 기록 백테스트(10일·20일 시점 예측 vs 실제) | 오차 측정 후 기준선(단순 일평균)보다 개선 |
| 공과금 추정 | 전년 동월 vs 전월 방식 오차 비교 | 더 나은 방식 채택 |
| 구매 상담 | 시나리오 50개(여유/빠듯/초과, 정기 지출 직전 등) | 숫자 일치 100%, 판단 규칙 일치 95% 이상 |
| 가드레일 | 인젝션 문구가 든 가맹점명, 범위 밖 질문, 개인정보 포함 질문 20개 | 위반 0건 |
| 실사용 | 2~4주 본인 사용 기록 | 미확인 결제 비율, 알림에 반응한 비율, 월 예산 달성 여부 |

## 9. 기술 스택과 구조

- **앱:** Flutter + Android 네이티브(Kotlin) 알림 리스너 브리지
- **로컬 저장:** SQLite(예: drift 또는 sqflite)
- **알림:** 로컬 알림 + 알림 버튼·인라인 동작
- **백그라운드:** WorkManager(0시 하루 기준액 계산, 알림 조건 검사)
- **서버:** Cloud Run 함수(Python) — LLM 중계, 툴 호출 형식 변환
- **LLM:** 분류는 jev(+저가 LLM 대비책), 상담·분석은 평가로 고른 상위 LLM(함수 호출). P1에서 상품설명서 검색용 임베딩
